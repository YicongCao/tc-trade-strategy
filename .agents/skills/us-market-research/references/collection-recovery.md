# Python 采集与 Codex 补查

每次 weekly / daily / realtime 都使用此流程。Codex负责研究判断，Python负责确定性校验与计算，不引入第二套模型服务。

1. 正常取 tc 包并运行 prepare，阅读返回的 gaps.json 和原始 snapshot.json。gaps 也可对现有快照重查。缺口包含缺失、过期、历史不足、空预测市场、查询截断及请求失败；这是工程质量检测，不能证明新闻完整或财务披露最新。
2. 按 core 优先补查：每个缺口最多两次尝试（原来源重试一次、替代官方来源一次），失败保留缺口。tc报价/日历失效直接重新取允许的tc接口，保存新tc包；当前SPY报价不能用昨日收盘替代。保留真实抓取时间，build截止须晚于全部取证；跨调度时段重新检查status。
3. 参考缺口 requirement / alternatives，用现有 MCP、网页搜索或只读浏览器获取公开资料。价格核验标的/币种/复权/交易时段；宏观核验序列/单位/发布时间；合约核验事件ID/结算定义/期限/报价时点。SEC失败查看IR原始披露，不把失败当成没有新财报。不新增付费订阅，不读取 sensitive、登录密钥或浏览器凭证。
4. 将精简补查输入存 results/<本次运行>/supplements.json，契约见 docs/data-contract.md。绑定原始快照hash，使用 build --supplements 合并到内存，原始快照不修改。冲突先复核，不能通过修改原快照掩盖；必要时重采集生成新的快照与补查文件。
5. build重新计算价格历史、指标和缺口。accepted仅表示通过结构/口径校验，来源真实性仍由Codex核验；context_only表示事实摘要待研究使用，不是修复数值缺口。宏观单点可用，但不生成20次观测变化；单日收盘不能计算SMA200/ATR14。来源或复权定义变化建立新比较基线，不能拼接历史。未提供完整历史时保留空指标。
6. 将补查新闻、CNN、披露结果分别按现有 news、indicator_observations、financials 契约用于分析；不要仅记录一条context_only就认为报告已引用。Polymarket补充事件必须再做event_reviews与三类观察筛选。财务五家公司逐一检查、ETF申赎、政策、新闻与五类主动主题研究始终执行，不能因缺口清单为空而省略。
7. 查看报告“采集、补查与剩余缺口”，解释缺口如何限制指导建议。原始请求失败记录可能仍保留；以补查状态和重新检测的序列缺口判断恢复。核心行情缺失停止完整报告；非核心失败允许附缺口发布。只发布正常报告输出，不提交补查文件、原始响应或日志。

公共采集恢复流程不触碰私人持仓；私人阶段是否执行服从当次有效用户指令与授权。不能因公开补查成功而推断账户数据可用。
