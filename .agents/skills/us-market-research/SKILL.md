# 美股主观交易研究

目标是解释市场在交易什么，并为数日至数周形成有确认、失效条件的交易剧本。读取仓库 `AGENTS.md`、[执行流程](../../../docs/research-workflow.md) 与 [数据契约](../../../docs/data-contract.md)。这里的相对路径从技能目录出发。

模式：
- `weekly`：最近完整美股交易周；检查前一周剧本的确认/失效条件，比较主线、价格量能和同定义事件预期，准备下一周催化剂。周末消息单列。
- `daily`：最近完整常规交易日；解释当日市场反应，盘后消息按实际抓取时刻单列，准备下一交易日观察清单。
- `realtime`：每次完整重查五类信息，标明盘前/盘中/盘后/休市，分别对照最近日报和实时报告。休市不把上次收盘报价称作实时成交。

用户未指定模式且问“现在发生什么”用 realtime；明确周报/日报时使用相应模式。支持用户指定研究日期、截止时间、重点主题。重点只改变分析深度，不省略其他领域。

## 执行

1. 确定真实当前时间，取 tc 交易日历（覆盖前 45 天至后 35 天），只读市场概览、报价（每批最多20个）、新闻（每次最多50条，按日或主题补查）。将剥离 MCP 包装后的市场数据存本地 tc JSON。只允许 AGENTS 中五个 tc 市场接口。已有 tc 授权直接复用。
2. 定时调用先 `git fetch origin main`，再用 `status --scheduled` 检查最近应生成周期；已发布则安静跳过。恢复运行只补最近周期，不逐日补旧报告。
3. `prepare` 采集 Polymarket、价格及宏观。保存输出路径，检查错误。每次检查五家公司是否有新披露：优先 `filings` 的 SEC 记录，失败则检查公司 IR/官方 filing 页面；不能把请求失败当作“没有新财报”。复用旧底稿时更新本次检查记录；发现新披露先核验再使用。
4. 阅读 [研究方法](references/methodology.md)，搜索官方公告、公司披露和可访问财经来源，核验 tc 社交线索。按数据契约写分析 JSON；人工摘要结算条件，匹配采集器的 rule_hash。保留来源发布时间、事件时间和抓取时间。未知时间写 null，不能填猜测时间。
5. `build` 后检查 Markdown、HTML、证据数据、缺口与剧本。首次使用或渲染代码变更时打开浏览器检验主题/事件筛选和历史周期筛选。
6. 校验通过后 `publish`，按已有授权提交并推送 origin main。推送失败保留本地文件，不强推，不擅自重置或合并用户改动。成功通知报告链接；未能核验核心状态则只留失败记录，明确原因。

不要直接在聊天中编一份报告代替入库。不得把全部新闻正文、原始 tc 对象或账户内容粘进报告。Markdown 与 HTML 都必须来自同一 evidence 对象。
