# 关联持仓附录

每次关联运行读取 `browser-target.json` 的url定位授权站点，复用Chrome现有登录会话；原标签不存在时可打开该授权URL。不读取Cookie、密钥或浏览器存储，不绕过登录或权限阻断。只读持仓和风险摘要，必要时查看跟单展示，不遍历全部历史订单。记录实际观察时刻；加载中占位和对照归零异常均标缺口。

逐个实际持仓形成 holding_reviews，不能只分析公共报告已有的五家公司：

- 公司：财报/电话会、指引、产品/订单、政策限制、融资等，查官方IR/SEC/政府并结合已核验新闻；对高相关Polymarket合约检查专门规则。
- 指数/行业ETF：查发行人、指数暴露与主要驱动，说明代表性权重公司财报、宏观政策和行业催化剂；不声称完整穿透所有成分。杠杆产品另列每日倍数、波动路径与持仓期限风险。
- 每项列事件事实、正式日期（含时区）和官方来源；日期不确定写null/未定，没有找到事件注明搜索范围。合约截止不等于公司事件日期。
- 将公共市场结论映射到持仓逻辑：改善与恶化情景、集中度和共同风险、确认/失效条件、期限和条件式调整建议；分清跟单和自主来源不确定性。没有用户风险预算，不给貌似精确的最佳仓位或自动交易指令。
- 私人附录可引用前期同类附录比较持仓/判断变化，须保留两个观测时点、成本口径和来源；不扫描账户原始文件或密钥目录。

输入字段：status（reviewed/unavailable）、observed_at（本次实际观察ISO时间；不可用时null）、summary、account_risk、positions（每项至少symbol及已核验数量/市值/来源标签，未知留空）、holding_reviews、gaps。每个持仓必须有唯一对应复核，含 symbol、catalysts（事件数组）、impact、upside_case、downside_case、confirmation、invalidation、horizon、guidance、sources。空仓正常核验可为reviewed且两个数组为空；加载失败不能写空仓。

不可用输入示例：`{"status":"unavailable","observed_at":null,"summary":"本次无法核验当前持仓，未生成调整建议","account_risk":null,"positions":[],"holding_reviews":[],"gaps":["浏览器连接或登录状态需要处理"]}`。使用写入器关联本次公共报告；不因网页无法读取省略私人结果。

禁止把账号、私人部署URL、登录信息、完整页面响应写进报告。URL定位配置留本地即可；写入器仅输出本地附录，不替代真实浏览器读取与研究。

阅读视图使用写入器的仓位图和逐标的条件卡片。提供已核验且明确分母的 `weight_pct`（占净值百分比）才绘图；缺失保持空值。账户解读用 `account_risk.interpretation` 写成短段，避免以原始字段代替风险解释。仅改版旧附录时保留原观察时间，并明确不是重新查询。
