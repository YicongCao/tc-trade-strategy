# IBKR 个人持仓与跟单复盘

用户已持续授权 weekly/daily/realtime 在公共研究后生成私人持仓附录，包括原生调度。按公共技能的关联流程执行，无需再次询问；独立复盘仍仅处理已授权的账户页面、所给记录和观点。公共市场调研由 `us-market-research` 承担。用户指定 Chrome 网站时复用其现有标签页与会话，不硬编码个人部署域名、账号或浏览器标签 ID。

## 只读边界与交付

- 通过当前可用的 CUA 浏览器 API 查看页面，先读返回文档再导航。允许查看持仓、账户摘要、表现、最近订单、交易记录及跟单组合的展示页面。
- 不点击交易、下单、平调执行、撤单、分享、添加组合或保存配置；不切换自动跟单状态，不读取账号设置、密钥、Cookie、浏览器存储或后台接口。读不到的信息标为缺失，不推测 API 或借用账户连接器扩大范围。
- 加载中、请求失败、空列表和未配置分别记录；不得将占位零值视为清仓、零收益或无历史。查看完成后尽量回到原页面。
- 个性化结论、截图及实际账户数据只在用户已指定的本地敏感目录保存；未指定时使用被 Git 忽略的 `sensitive/position-reviews/{日期}/{运行时间}/`。先检查忽略规则与未跟踪状态，不读取目录内无关资料。默认不保存原始截图或全页快照。
- 技能及其参考文件只保存去标识的方法和界面语义；不得包含部署域名、账号、真实持仓与金额、订单明细、完整网页响应或私密观点原文。个人报告不写入 `reports/`，不加入公共索引，不调用市场技能的 `publish`，不提交或推送。

## 关联报告

按 [关联附录流程](references/linked-review.md) 读取当前持仓，逐一查询公司/指数催化剂并关联公共研究。站点定位只读 `sensitive/position-reviews/browser-target.json`，不读取其他敏感配置；没有可用浏览器会话或站点无法访问时生成 status=unavailable 的失败附录，不使用旧持仓冒充当前。不读取凭证、不扩大浏览器权限。

## 读取与解释

先读 [界面字段与局限](references/trader-ui.md)。按分析所需选择页面，不必每次遍历全部页面。

1. 记录实际观察时间、页面状态、所选窗口、可见数据更新时间及报价时点。未知时区或成交时间明确缺失；周末页面数字刷新不证明发生交易。
2. 分开保存实际持仓、界面对照数量、差异标签、用户解释与来源判断。用户在此工作流中说明“需平仓”代表自主购买的额外标的：作为用户约定保留，不解释成风控命令、强平通知或卖出建议。只有跟单目标正常加载、语义一致时才据此分类；配置缺失、目标突然全部归零或前后矛盾时标为来源待核实。
3. 非零对照数量不证明全仓源于跟单。可能存在手动增加同一标的、分批成交、比例换算、取整或目标更新延迟；没有来源日志时，不把这些可能性写成事实，也不根据当前标签反推历史订单来源。
4. 将信号提供者的市场判断、其组合调整、程序生成目标、实际成交、用户额外操作分开。用户转述观点是观点证据，不能证明提供者已做相应交易。没有带时点的目标历史，不计算跟单超额收益或把损失归因于某个人。
5. 用净清算值衡量集中度，区分股票市值、现金借款、购买力、可用资金、超额流动性与维持保证金；有币种明细时逐币种解释。不得用购买力代替现金或把负现金直接判为即将强平。杠杆 ETF 的日内敞口近似与多日路径效应分开。
6. 交易记录按当前窗口及分页说明覆盖范围；成交行可能是部分成交，不能直接等同交易决策次数。实盘与历史 CSV 的数量、成本、盈亏、时间口径存在差异时分别展示，未经核对不覆盖旧报告或跨来源相减。

## 观点检验与账户建议

对长篇跟单观点，按 [假设检验方法](references/thesis-review.md) 拆解；不把一次性价格目标、波浪标签或某月预测固化为技能规则。

复用已有公共市场报告时检查截止时间与质量，必要时通过允许的 tc 市场工具和官方资料更新。仅向公共行情工具提供所需证券代码，不传账户数量、成本或交易记录。私人分析不自动触发完整公共报告发布。

输出应让用户分清：
- 账户事实与来源置信度，跟单／自主／混合或未知的划分依据；
- 原观点哪些得到证据支持、哪些只是推断、哪些已失效；
- 市场问题缓解、继续恶化和高波动震荡分别如何影响组合；
- 条件式调整的催化剂、确认条件、失效条件、观察期限和反证。

数量示例须列出价格时点、费用与税务遗漏，不能伪装为已执行订单。压力测试标为假设，不给主观情景附上未经估计的概率。风险预算不足时先展示敏感性与取舍，避免用信号提供者的信心替代用户的承受能力。
