# 2026-08-12 AI 输出截断与重复告警的处置

两件事：一件需要在平台 UI 上修、MCP 做不了；一件是已经驳回过的告警又报了一次。

## 一、赌狗的再平衡 AI 输出截断

平台报错原文：

> 策略「主题动量赌狗」的再平衡 AI 没产出任何内容：输出预算被推理链耗尽（length）。请到「AI 供应商」页调大该供应商的最大输出长度（推理模型建议 ≥ 16k），否则每轮再平衡都会白跑。

### 根因

`list_ai_providers` 读到的当前供应商：

| 字段 | 值 |
| --- | --- |
| name | `deepseek-v4-pro-from-txy` |
| model | `deepseek-v4-pro-202606` |
| protocol | `openai-completions` |
| api_base_url | `https://tokenhub.tencentmaas.com/v1` |
| temperature | 0.7 |
| **`enable_thinking`** | **true** |
| disabled | false |
| used_by_strategies | **total 7 / active 5** |

这是一个开了思维链的推理模型。推理内容与最终答案共用同一个 `max_tokens` 预算，预算偏小时推理链会把额度吃光，返回的 `finish_reason` 就是 `length`，正式输出为空。

**注意 `list_ai_providers` 不返回最大输出长度这个字段**，所以从 MCP 侧看不到当前值是多少，只能到 UI 上看。

### 这件事不在冒烟

昨晚（8/11）赌狗的主分析完全正常：两轮分析、12 条决策、成交 1 笔。被截断的只有再平衡那一次调用。

更关键的是，**再平衡即使跑通，昨晚也不会换任何仓**：

| 轮次 | 时间(UTC) | 持仓数 | 持仓 confidence | 新候选 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 第 1 轮 | 13:31 | 4（有空位） | PLTR .85 / NET .85 / ANET .82 / SAP .85 | AXTI .85、QMCO .82 | AXTI **成交**填满空位，QMCO skipped |
| 第 2 轮 | 17:32 | 5（已满） | NET .80 / SAP .90 / ANET .82 / PLTR .85 / AXTI .82 | SMCI .87 | SMCI skipped |

第 2 轮是唯一需要再平衡介入的场景（满仓 + 有新候选）。再平衡的判据是「新候选置信度 − 最弱持仓置信度 > 0.10」，而当时最弱持仓 NET 是 0.80、最强新候选 SMCI 是 0.87，**差值 0.07 够不到阈值**。所以再平衡跑通与否，结果都是不换仓。

这同时说明 8/06 那条 E 改进（给在手持仓设 confidence 下限 0.80）**正在按设计工作**——持仓评分全部落在 0.80–0.90，新候选被压在 0.85 上下，两者差距天然小于 0.10。换句话说，再平衡本来就被设计成"大部分时候不该动手"，截断造成的实际损失接近于零。

**结论：该修，但不是紧急故障。** 真正的代价是每轮浪费一次 token 消耗，以及行为不确定——某些轮次预算够用时再平衡又会生效，导致表现时灵时不灵。

### MCP 修不了

写工具白名单只有 `create_strategy` / `update_strategy` / `archive_strategy` / `unarchive_strategy` / `confirm_proposal`，**全部作用于策略，没有任何修改 AI 供应商的工具**。`list_ai_providers` 是只读的。

所以最大输出长度只能在平台「AI 供应商」页上改。

### 需要在 UI 上做的事

1. **先记下当前的最大输出长度数值**，用于前后对照（本文档留空待填）
2. 调到 **≥ 16384**
3. 保存后回读核对——本仓库记过「UI 的保存成功提示不可信」这个坑，有过一整轮 4 个策略界面显示保存成功、接口读出来一项都没生效的先例

两点风险：

- 该供应商**被 7 个策略共用（5 个 active）**，改的是共享设置。抬高上限本身安全（它是天花板不是目标值，非推理调用不会因此变长），但推理模型从此会输出完整思维链，**所有策略的 token 消耗与延迟都会上升**
- `input_price_per_mtok` 与 `output_price_per_mtok` 都是 `null`，**成本没有在跟踪**，涨了也看不出来

### 改完后怎么验证

**不能用「没有换仓动作」当失败证据。** 如上所述，confidence 纪律本来就把差距压在 0.10 以内，再平衡跑通了大概率也是不换仓，看不到任何外部动作。

可用的判据：

- 下一个交易时段后，平台不再报「AI 输出被截断，再平衡白跑」
- `list_decisions` 确认赌狗仍有正常决策产出，说明抬高上限没有影响主分析
- 想要正面证据的话，对改动后某一轮的决策调 `get_decision_detail(include_ai_text=true)`，检查原始响应是否完整结束

### 若改完仍然截断

退路是把赌狗切到另一个闲置供应商：

| 字段 | 值 |
| --- | --- |
| name | `deepseek3.1` |
| model | `deepseek-v3.2` |
| temperature | 0.6 |
| `enable_thinking` | **false** |
| used_by_strategies | 0 / 0 |

不开思维链就不存在推理链占预算的问题。这个切换可以用 `update_strategy` 改 `ai_provider_id` 完成，MCP 做得到。

**但这是备选不是首选**：换模型会污染 8/06 那批改动的观察窗口——8/11 复盘刚说过赌狗的降频改造只有 3 个交易日样本、还需要再观察 5 天，中途换模型会让「换手下降是不是改对了」这个问题失去对照。

## 二、6 项风控告警：与 8/11 同一批，判定不变

平台这次报的是 DRAM 网格 3 项、长持标普 500 3 项，内容是止损 50% 过宽、日内熔断 −50% 过宽、止盈 50% 过宽。

**这是 8/11 那 9 项的子集。** 当时 XPEV 也在列，暂停后就不再被扫描，剩下这两个 active 策略的 6 项。完整论证见 `reviews/2026-08-11-risk-config-fix.md` 第三节，此处只复述结论：

1. 这几个字段**必填且没有关闭开关**，服务端校验范围是止损 0.5–50、日内熔断 −50 ~ −0.5，**50 与 −50 就是合法区间内最接近「禁用」的取值**
2. 在 AI 策略路径上它们是**喂给 LLM 的软参考，不是硬触发**
3. 长持 VOO 是 `trading_mode: open_only`，**引擎层面不能卖**，三项全是死字段，改成任何数字都不会执行
4. 给 DRAM 收紧止损会让 LLM 收到「浮亏接近 X% 时考虑平仓」的提示，**与网格「越跌越买」的逻辑直接冲突**；它的退出规则写在提示词里（跌破 34.92 清仓），比一个百分比阈值精确

**处置：不改。** 这批告警会在每次扫描时重复出现，属于预期内的噪声。为免以后每次都重新论证一遍，已把结论固化为 `.cursor/rules/risk-config-warnings.mdc`。

## 三、一条需要留意的观察：AXTI 第三次建仓

昨晚赌狗唯一的成交是 AXTI 237 股 @ 73.0565。这只票的完整历史：

```
8/03 16:37  买 467 @ 68.7844
8/04 13:41  硬止损卖出 @ 62.6687          −2,860.20
8/05 17:33  买 427 @ 73.2466
8/05 18:33  被 rebalance 改写平仓 @ 70.9245  −995.43
8/11 13:31  买 237 @ 73.0565            ← 第三次，仍在 73 附近
```

累计已实现 **−3,855.63**，当前浮盈 +170.64。

提示词第 12 条写的是「单只相对成本亏损达到 8% → 立即 sell/close，该标的 5 个交易日内不得再买」。从哪次离场起算会得出不同结论：

- 从 8/04 的硬止损起算：8/05、8/06、8/07、8/10、8/11 = **5 个交易日，刚好合规**
- 从 8/05 的最后一次离场起算：8/06、8/07、8/10、8/11 = **4 个交易日，早了一天**

**但这个争论意义不大，因为这条规则实际上没有任何东西在执行。** 8/06 复盘的 H 条说得很清楚：finviz 筛选器没有记忆，AXTI 只要重新满足技术条件就会再进池；LLM 的上下文里也没有「这只票被止损过」的状态。纯文本规则约束不了无状态的循环，H 条至今未实现。

目前 AXTI 是浮盈，不构成问题，仅作记录。若要真正落实第 12 条，需要的是外部状态支撑（例如每次复盘手工把近期被止损的标的写进提示词的静态排除名单），而不是把规则再写一遍。
