# Trade Copilot 平台能力

Trade Copilot 是一个智能化交易平台。本文按功能域整理平台能力，并标注**每项能力对本仓库写策略意味着什么**——哪些可以直接复用、哪些需要在本地自己实现。

## 1. 交易策略与执行

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 网格交易引擎 | v1.95.0+ | 支持实盘与回测；可按**分时段滑点和手续费自动平移**网格；提供必亏配置软警告与收益曲线图表 |
| 两阶段再平衡 | v1.1.0, v1.72.0+ | 从全局视角统筹资金分配；满仓状态下支持 AI 换仓或加仓 candidates 评估 |
| 多层级风控守卫 | v1.73.7, v1.93.0+ | 独立硬止损 `stop_loss_pct`；每日亏损硬熔断 `daily_pnl_stop_pct`；高波动率（VIX 规管）下的开仓硬门控 |
| 多市场多币种 | — | 兼容美股、港股交易时段与假期日历；跨币种汇总按市场分组展示 |

**对本仓库的含义**

- 平台的网格引擎已经内置了"分时段滑点/手续费自动平移"和"必亏配置检测"。这两点正是自己写网格最容易漏的地方：本地网格实现必须把**费用与滑点算进网格间距**，并加一条前置校验——当格子间距小于单次往返成本时直接报警，否则回测出来的高胜率是假的。
- "必亏配置"值得在本地做成硬断言而不是警告：`格子间距收益 <= 买入成本 + 卖出成本` 时拒绝运行。
- 再平衡是**组合层**逻辑，和单策略信号是两层。本地引擎最好一开始就把"信号层（产出目标仓位）"和"资金分配层（把目标仓位换算成订单）"分开，否则后面加再平衡要重写。
- 风控三件套（硬止损、日亏熔断、波动率门控）应作为回测引擎的独立可插拔模块，在信号之后、下单之前统一拦截，而不是散落在各策略里。

## 2. AI 分析与复盘

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 跨策略顶级 AI 复盘 | v1.58.0+ | 独立 AI 分析会话，支持 `@` mention 跨策略对话 |
| 两段式写操作与提案卡片 | v1.110.0+ | AI 生成策略变更/创建提案，用户两段式确认后执行；字段级 diff 展示与异常重试 |
| 深度思考与流式输出 | v1.111.0+ | 模型思考过程可展开；用 Redis Pub/Sub 解决多实例下"思考中"卡顿 |

**对本仓库的含义**

- 平台的策略是 **AI 驱动**的（`system_prompt` + `market_data` 喂给 LLM 出决策），和本仓库计划写的**规则驱动**策略是两种范式。本地规则策略的价值正在于此：它是 AI 策略的**基准线（baseline）**。如果 AI 策略跑不过一个简单的双均线或网格，那 AI 部分就没有产生 alpha。
- 建议本地实现和平台策略同标的、同区间的规则版对照组，用同一套指标参数，作为复盘时的参照。
- 写操作走两段式确认提案——注意目前 MCP 并未暴露提案类工具，改策略只能在 UI 做。

## 3. 市场概览与指标监控

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 0AMV 活跃市值监控 | v1.105.0+ | 换手衰减模型，跟踪大盘/特定指数的趋势反转点 |
| KLineChart 专业金融图表 | v1.109.0 | 上证综指等真实 K 线主图 + 0AMV 副图叠加 |
| 板块表现热力图 | v1.24.0 | 自适应动态情绪增强色阶与 Label 智能显隐 |

**对本仓库的含义**

- 0AMV 可通过 `get_cn_market_timing` 直接取用（`regime` 多空区间 + `signal` 反转日），这是**现成的 A 股大盘择时开关**，不用自己造。典型用法：`regime = -1` 时禁止新开仓或降低网格资金占用。仅限 A 股大盘，美股标的不适用。
- 板块 `turnover` + `changePct` 可以作为轮动策略的选股上游过滤。
- 市场概览的 `temperature`（估值 + 情绪合成）和 `vix` 可作为仓位缩放因子，但只有最新快照、无历史回查，**无法用于回测**，只能用于实时决策。回测里要做同类门控得自己另找 VIX 历史数据。

## 4. 消息面采集与大模型分析

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 多源网络爬虫 | v1.91.0+ | 财联社（CLS）、FinancialJuice、Twitter、Truth Social |
| 资讯前置过滤与注入 | — | URL 推文自动抓取原网页内容后喂 AI；策略级"市场环境与关键事件注入"开关 |

**对本仓库的含义**

- 注意能力边界差异：平台采集了 CLS / FinancialJuice / Twitter / Truth Social 四源，但 **MCP 的 `list_news_for_period` 只暴露 Twitter 和 Truth Social**，且不含传统财经新闻、研报、公告。
- 消息面数据有 `sentiment` 和 `impact` 标签，理论上可做事件驱动策略，但**存在前视偏差风险**：`analysis` 是 AI 事后打的标，采集与分析时间未必早于价格反应。用于回测前必须先核对 `posted_at` 与分析产出时间的先后。稳妥做法是初期不把消息面纳入回测，只作为实盘的定性参考。

## 5. 系统集成与基础设施

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| 站内 MCP 接入 | v1.112.0+ | 接入指引、OAuth 认证，提供多项只读/写工具 |
| 多渠道通知推送 | — | 通知规则配置，支持 Bark 等通道按账号/平台分组推送订单成交、系统告警、每日简报 |
| 长桥证券对接 | v1.29.0+ | 长桥凭证健康探活与自动热更新缓存，防止过期导致下单被拒 |
| 分享系统 | v1.69.0 | 投资组合、交易记录、网格收益生成带风险提示的站内公开分享链接 |

**对本仓库的含义**

- MCP 是本仓库与平台之间唯一的程序化通道，**只读与写工具都已可用**（详见 `trade-copilot-mcp.md`）。本地策略上实盘可以走 `create_strategy` / `update_strategy` 的两段式提案，不必再靠人工在 UI 里敲——但每次提案都要把 diff 给用户确认。
- 券商侧是长桥。如果本地回测要贴近实盘，费率与最小交易单位应按长桥的规则设置（港股手数、美股碎股支持等），而不是用通用假设。
- 凭证过期会导致下单被拒——本地若将来接实盘，同样需要凭证探活，不要假设 token 长期有效。

## 6. 运维与成本观测

| 能力 | 版本 | 说明 |
| --- | --- | --- |
| AI 用量与成本统计 | v1.36.0+ | 记录 `ai_usage_logs`，展示 Token 单价与实际开销；对 Prompt Cache（`cached_tokens`）命中率专门埋点 |
| 全站 PWA | v1.23.0 | 完整 Service Worker 缓存，移动端可安装为独立 App；刘海屏安全区自适应、表格首列 Sticky |

**对本仓库的含义**

- AI 策略有**每次决策的 token 成本**，规则策略没有。做策略对比时，AI 策略的净收益应扣掉 AI 调用成本，否则和规则策略的比较不公平。`analysis_interval=30` 分钟意味着一个交易日约十几次调用，长期累积不可忽略。
- 这也是本地规则策略的一个天然优势项，值得在对比报告里单列一行"运行成本"。

## 能力归属速查

写策略时先查这张表，决定某个功能是"调平台"还是"自己写"。

| 需求 | 平台已有 | MCP 支持 | 本地需自建 |
| --- | --- | --- | --- |
| 网格实盘与回测 | 有 | 无工具 | 需要（本仓库核心） |
| A 股大盘择时（0AMV） | 有 | 可读 | 直接调用即可 |
| 交易日历 / 假期 | 有 | 可读 | 直接调用即可 |
| 实时行情（≤20 标的） | 有 | 可读 | 直接调用即可 |
| 历史 K 线（批量、长周期、分钟级） | 有 | **受限**（单标的 ≤120 根、无分钟级） | 需要另找数据源 |
| 回测引擎与评估指标 | 有 | 无工具 | 需要（本仓库核心） |
| 手续费 / 滑点模型 | 有（分时段） | 只能从成交流水反推 | 需要 |
| 组合再平衡 | 有 | 无工具 | 需要（第三阶段） |
| 风控（止损/熔断/波动门控） | 有 | 可读可写（`update_strategy` 改 `risk_config`） | 需要（可复用平台字段口径） |
| 消息面情绪标签 | 有（四源） | 部分（仅两源社交） | 暂不纳入回测 |
| VIX / 市场温度历史序列 | 有（仅最新快照对外） | **不可回查** | 回测需另找数据源 |
